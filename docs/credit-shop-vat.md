# VAT รายร้านเครดิต

เปิดที่ **จัดการร้านค้า → ร้าน → การชำระเงิน → คิด VAT เพิ่ม 7%** หรือปุ่ม **ตั้งค่า VAT** ในรายละเอียดลูกหนี้ (แอดมินเท่านั้น) ค่าเริ่มต้นปิดทุกร้าน ใช้กับการขายน้ำแข็งแบบเครดิตของร้านประจำที่สร้างใหม่หลังเปิดใช้ ไม่รวมค่าเช่าถัง งานอีเวนต์ หรือใบกำกับภาษี

## ยอดเงินและเอกสาร

- ราคาสินค้าเป็นราคาก่อน VAT: 1,000 + 70 = 1,070 บาท ระบบรวมราคาต่อรายการที่ปัดเป็นสตางค์ แล้วปัด VAT สองตำแหน่งหนึ่งครั้งต่อบิล
- `delivery_charges.original_amount` เป็นยอดสุทธิรวม VAT ตามความหมายเดิมของยอดเรียกเก็บ เพิ่ม `subtotal_amount`, `vat_rate`, `vat_amount` เป็นข้อมูลคงที่ของบิล
- วงเงินเครดิต ยอดค้าง การรับชำระ และการยกเลิกใช้ยอดสุทธิเดียวกัน รายการเก่ามีอัตรา 0 และยอดเดิม เอกสารที่เก็บไว้ไม่ถูกเขียนทับ
- ใบวางบิลใหม่เก็บยอดก่อนภาษี ภาษี และยอดเต็มของบิลที่เลือก แม้เคยจ่ายบางส่วนแล้ว โดย `total_amount` ยังคงเป็นยอดวางบิล ณ วันออกเอกสาร และ `outstanding_amount` เป็นยอดคงเหลือปัจจุบัน
- ตอนพิมพ์แสดงยอดเต็ม หักชำระก่อนวางบิล เป็นยอดวางบิล แล้วแสดงชำระหลังวางบิลและยอดคงเหลือ ใบวางบิลเก่าที่ไม่มี snapshot การแยกภาษีใช้รูปแบบเดิม
- ระบบเดิมอนุญาตเฉพาะยกเลิกใบส่งแล้วลงขายใหม่ และห้ามแก้หลังปิดรอบ/ยกเลิกบิลที่มีการรับชำระ การเพิ่ม VAT ไม่เปลี่ยนกติกานี้ ยกเลิกอ้างอิงยอดภาษีของบิลเดิม ส่วนการลงขายใหม่เป็นรายการใหม่ตามการตั้งค่าขณะนั้น

## API และคำขอค้าง

`shop_payment_profiles.vat_enabled` เพิ่มใน POS context และรายการลูกหนี้ การตั้งค่าถูกตรวจด้วยสิทธิ์ RLS เดิมของแอดมิน และปิดอัตโนมัติเมื่อเปลี่ยนร้านออกจากเครดิต รวมถึงการแก้เงื่อนไขหลายร้าน

หน้าส่งสินค้าเรียก `record_delivery_with_vat_check` พร้อม `p_expected_vat_rate` และ `p_expected_total` ที่พนักงานเห็น ฐานข้อมูลคำนวณยอดจริงและตรวจในธุรกรรมเดียวกัน ถ้าต่างจะ rollback ทั้งรายการ พร้อม detail `VAT_OR_PRICE_CHANGED` หน้าจอโหลดข้อมูลใหม่ให้ตรวจยอดก่อนส่งอีกครั้ง

คำขอที่สำเร็จแล้วใช้ idempotency key เดิมเพื่อคืนบิลเดิม แม้ VAT ของร้านเปลี่ยนภายหลัง คำขอเก่าที่ไม่มี snapshot และยังไม่เคยสำเร็จต้องตรวจข้อมูลใหม่ก่อนบันทึก ไม่เติม VAT ลงคำขอเก่าโดยเงียบ ๆ

Offline contract รองรับ `expectedVatRate` (0 หรือ 7) ตรวจยอดรวมกับรายการสินค้า และเพิ่มอัตรา VAT ใน payment-profile fingerprint เฉพาะเมื่อเปิด VAT เพื่อรักษา hash ของข้อมูลเดิม ตัวประมวลผล full-offline ที่จะพัฒนาต่อควรใช้ RPC ที่ตรวจยอดนี้ พร้อมการตรวจราคาและ fingerprint ตาม `employee-full-offline-plan.md`

## การนำขึ้นใช้งาน

นำขึ้นใช้ตามลำดับ: ลง migration `0216_credit_shop_vat.sql` เพื่อเพิ่มคอลัมน์และ RPC ใหม่ → อัปเดต frontend ให้เรียก `record_delivery_with_vat_check` → ลง migration `0217_close_unchecked_credit_delivery.sql` เพื่อตัดสิทธิ์เรียก RPC เดิมโดยตรง → เปิด VAT ให้ร้านที่ต้องการผ่านหน้าตั้งค่า ระหว่างอัปเดต frontend ยังไม่มีร้านใดเปิด VAT; หลังลง `0217` เครื่องที่ยังเปิดแอปเวอร์ชันเก่าต้องรีเฟรชก่อนส่งสินค้า

การทดสอบ `credit-shop-vat.integration.test.mjs` ลง migration จริงทั้งหมดใน PGlite และตรวจข้อมูลเก่า การขาย/วงเงิน การวางบิลผสม การจ่ายบางส่วน retry การยกเลิก และค่าเช่าถัง ส่วน `credit-vat.test.tsx` ตรวจยอด หน้าสรุป การพิมพ์ และ offline contract
