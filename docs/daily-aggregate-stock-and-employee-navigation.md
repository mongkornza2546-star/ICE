# ข้อกำหนดสต๊อกรวมรายวันและหน้าหลักพนักงาน

สถานะ: ข้อตกลงสำหรับพัฒนาระบบ  
วันที่สรุป: 28 กรกฎาคม 2569

## 1. เป้าหมาย

ปรับระบบให้ใช้ **สต๊อกรวมรายวัน** เป็นยอดหลัก แทนการใช้ยอดแยกตามรถ จุดปฏิบัติงาน หรือจุดถือครองของพนักงานเป็นเงื่อนไขก่อนขาย

POS ต้องสนใจเพียง:

- ร้านที่ส่ง
- ชนิดน้ำแข็ง
- จำนวนที่ขาย
- ผู้บันทึก
- วันที่ให้บริการ

การลืมบันทึกโอนน้ำแข็งระหว่างรถ จุดปฏิบัติงาน หรือพนักงานต้องไม่ทำให้ POS บันทึกไม่ได้ และต้องไม่ทำให้ยอดขายถูกตัดซ้ำ

## 2. แหล่งจริงของสต๊อก

ยอดสต๊อกหลักคำนวณแยกตามวันที่ให้บริการและชนิดน้ำแข็ง:

```text
คงเหลือตามระบบ
= ยอดสั่งจากโรงงานทุกครั้งของวัน
− ยอดขายที่บันทึกผ่าน POS
− ยอดเติมน้ำแข็งเดิมที่ยัง active (ถ้ามี)
− ยอดเสียหายหรือละลาย
− ยอดส่งกลับโรงงาน
± ส่วนต่างจากการตรวจนับตอนปิดวัน
```

ข้อกำหนดสำคัญ:

- ยอดสั่งเพิ่มระหว่างวันต้องนำมาบวกกับยอดสั่งเดิม
- รถที่รับน้ำแข็งยังเก็บไว้เป็นข้อมูลประกอบของคำสั่งโรงงาน แต่ยอดของรถทุกคันรวมเป็นสต๊อกรายวันเดียว
- ยอดสั่งโรงงานถือเป็นยอดตั้งต้น เพราะไม่มีการตรวจรับจริงตอนขึ้นรถ
- ระบบต้องไม่สรุปอัตโนมัติว่าส่วนต่างเกิดจากโรงงาน
- สต๊อกของวันใหม่เริ่มจากยอดสั่งใหม่ ไม่มีสต๊อกยกมาจากวันก่อน

## 3. การบันทึกขายผ่าน POS

เมื่อพนักงานบันทึกขาย ระบบต้องตัดจากสต๊อกรวมของวันโดยตรง ไม่ตรวจสอบว่า:

- พนักงานเคยเบิกน้ำแข็งเท่าไร
- น้ำแข็งอยู่บนรถคันใด
- น้ำแข็งอยู่ที่ตึกหรือจุดปฏิบัติงานใด
- พนักงานมีจุดถือครองหรือไม่
- มีการบันทึกโอนเข้าจุดถือครองแล้วหรือไม่

กติกาจำนวนและราคา:

- POS ใช้จำนวนเดียวสำหรับคิดเงินและตัดสต๊อก
- รองรับจำนวนครั้งละ `0.5` ถุง
- การขาย `0.5` ถุงคิดเป็นครึ่งหนึ่งของราคาต่อถุง
- ไม่เพิ่มช่อง “จำนวนตัดสต๊อกจริง” ใน POS เพื่อไม่เพิ่มขั้นตอนและความสับสน
- หากสต๊อกรวมไม่พอ ระบบต้องบล็อกการขายและให้หัวหน้าบันทึกยอดสั่งเพิ่มก่อน
- รายการที่บันทึกซ้ำด้วย idempotency key เดิมต้องไม่สร้างยอดขาย ยอดเงิน หรือยอดตัดสต๊อกซ้ำ

## 4. การเบิกและการโอนภายใน

การเบิกหรือโอนน้ำแข็งจากรถกลางไปให้พนักงาน รถเล็ก หรือจุดปฏิบัติงาน เป็น **ข้อมูลการกระจายภายใน** ไม่ใช่ยอดขายและไม่ใช่ยอดออกจากกิจการ

ข้อกำหนด:

- ใช้หน้าโอนออกแบบต้นทาง–ปลายทางเดิม
- เก็บผู้บันทึก ผู้รับ ชนิด จำนวน และเวลาเพื่อดูย้อนหลัง
- การเบิกเป็น snapshot ตามที่มีผู้บันทึก ไม่ใช่ยอดหลักของสต๊อก
- การโอนภายในไม่เพิ่มหรือลดสต๊อกรวมรายวัน
- การโอนไม่จำกัดจำนวนที่ POS ขายได้
- การไม่ได้บันทึกโอนไม่บล็อก POS
- การโอนไม่เป็นเงื่อนไขก่อนปิดวัน
- หน้าพนักงานไม่ต้องมีขั้นตอน “รับน้ำแข็งเข้าจุดถือครอง” ก่อนเลือกร้าน

ห้ามแก้ระบบเพียงให้ POS ตัดจากรถกลาง แต่ยังนำรายการโอนไปหักยอดรถกลางซ้ำ เพราะจะเกิดการตัดสองครั้ง

## 5. รายการเติมน้ำแข็งเดิม (ยกเลิกการใช้งาน)

ระบบเลิกสร้างรายการ “เติมน้ำแข็ง” ที่ไม่ผูกกับร้านแล้ว ทุกบทบาทถูกปิดสิทธิ์เรียก RPC สำหรับสร้างรายการใหม่ และหน้าพนักงานไม่มี action นี้

ข้อมูลที่บันทึกไว้ก่อนยกเลิกฟีเจอร์ยังคงถูกนำมาคำนวณสต๊อกรวมเพื่อรักษาความถูกต้องย้อนหลัง หัวหน้าและแอดมินดูและยกเลิกได้เฉพาะรายการเดิมที่ยัง active โดยต้องระบุเหตุผลและเก็บ audit log ตามเดิม

## 6. Bottom tab bar ของหน้าพนักงาน

หน้าหลักพนักงานมี bottom tab bar เพียง 3 ปุ่ม เรียงดังนี้:

### 6.1 เบิก

ใช้สำหรับ:

- บันทึก snapshot ว่าพนักงานนำอะไรออกจากรถบรรทุกกลางเท่าไร
- ดูรายการเบิกหรือโอนที่เกี่ยวข้อง

รายการเบิกไม่กระทบสต๊อกรวม และไม่สามารถสร้างรายการเติมน้ำแข็งใหม่ได้

พนักงานไม่สามารถตรวจนับหรือปิดสต๊อกทั้งวันได้ การตรวจสอบและปิดวันยังเป็นสิทธิ์ของหัวหน้าและแอดมิน

### 6.2 POS

- เป็น tab เริ่มต้นหลังเข้าสู่ระบบ
- ใช้เลือกร้านและบันทึกส่งน้ำแข็ง
- ตัดจากสต๊อกรวมรายวัน
- การสลับ tab ขณะมีรายการที่ยังไม่บันทึกต้องเตือนก่อนออกจาก POS

### 6.3 เก็บเงิน

แสดงเฉพาะร้านที่:

- มีรายการซื้อจริงในวันที่ให้บริการปัจจุบัน
- มี charge ที่ยังใช้งาน
- ยังมียอดที่ต้องเก็บ
- ใช้เงื่อนไขชำระทันทีหรือเก็บท้ายวัน

ต้องไม่แสดง:

- ร้านที่ไม่มีรายการซื้อในวันนั้น
- ร้านที่ชำระครบแล้ว
- ร้านเครดิตที่ยังไม่ถึงขั้นตอนเก็บเงิน
- ยอดค้างจากวันก่อนในคิวงานพนักงานของวันนี้

ยอดค้างวันก่อนและลูกหนี้เครดิตยังดูได้จากหน้าการเงินของหัวหน้าหรือแอดมิน

## 7. การปิดสต๊อกสิ้นวัน

หัวหน้ากรอกยอดนับจริงรวมต่อชนิด โดยรวมของที่เหลือจากรถและทุกจุด ไม่ต้องกรอกยอดย้อนหลังแยกตามพนักงาน

ตัวอย่าง:

```text
ยอดสั่งทั้งหมด                120
ยอดขายจาก POS                  95
เติมน้ำแข็งเดิม                 0
เสียหาย/ละลาย                   3
ควรเหลือ                       22

นับจริงรวม                     20
ส่วนต่าง                       -2
```

กติกา:

- แสดงยอดตามระบบ ยอดนับจริง และส่วนต่างแยกตามชนิด
- หากมีส่วนต่าง ต้องกรอกหมายเหตุก่อนยืนยันปิดวัน
- ใช้คำอธิบายเริ่มต้นว่า “ส่วนต่างยังไม่ทราบสาเหตุ”
- ไม่ต้องอนุมัติผลต่างแบบรายจุด
- ไม่ต้องนับครบทุกจุดถือครองก่อนปิดวัน
- เมื่อปิดวัน ระบบบันทึก snapshot ยอดรวมและส่งยอดนับจริงที่เหลือกลับโรงงาน
- หลังปิดวัน สต๊อกของวันนั้นต้องเป็นศูนย์และห้ามสร้างรายการขายหรือเคลื่อนไหวสต๊อกใหม่

## 8. Interface ที่ต้องมี

ระบบควรมี interface กลางสำหรับสต๊อกรวมรายวัน เพื่อให้ POS, Dashboard, ข้อมูลเติมน้ำแข็งเดิม และการปิดวันใช้สูตรเดียวกัน

ข้อมูลสรุปต่อชนิดอย่างน้อยประกอบด้วย:

- ยอดสั่งทั้งหมด
- ยอดขายจาก POS
- ยอดเติมน้ำแข็งเดิม (เพื่อความถูกต้องย้อนหลัง)
- ยอดเสียหาย/ละลาย
- ยอดส่งคืนโรงงาน
- ยอดคงเหลือที่ใช้ได้
- ยอดนับจริงและส่วนต่างเมื่อปิดวัน

การบันทึก POS, เสียหาย, ส่งคืน และปิดวันต้องใช้ lock ตามวันที่ให้บริการชุดเดียวกัน เพื่อป้องกันการตัดพร้อมกันจนยอดติดลบ

## 9. ความเข้ากันได้กับข้อมูลเดิม

- เพิ่ม migration ใหม่ต่อจาก migration ล่าสุด ห้ามแก้หรือเขียนทับประวัติ migrations เดิม
- รักษารายการส่ง ราคา charge การรับเงิน revision และ audit เดิม
- รายการเก่าที่เคยตัดตามจุดต้องยังสรุปยอดรวมย้อนหลังได้ถูกต้อง
- รายการ legacy ที่ไม่เคยอยู่ใน stock ledger ต้องไม่ถูกนำมาตัดสต๊อกย้อนหลัง
- คำสั่งโรงงานเก่าที่มียอดรับจริงแบบ legacy ต้องคงใช้ยอดรับจริงเดิม
- ปิดหรือยกเลิก RPC รุ่นเก่าที่สามารถสร้างรายการส่งโดยไม่ผ่านราคาและการเงิน

## 10. เกณฑ์รับงาน

- พนักงานเห็น bottom tab bar เฉพาะ “เบิก”, “POS” และ “เก็บเงิน”
- POS ใช้งานได้โดยไม่ต้องเบิกหรือรับน้ำแข็งเข้าจุดถือครองก่อน
- รายการโอนภายในไม่เปลี่ยนยอดรวมและไม่ทำให้ POS ถูกตัดซ้ำ
- ขายครึ่งถุงได้และคิดราคาครึ่งหนึ่ง
- ทุกบทบาทไม่สามารถสร้างรายการเติมน้ำแข็งใหม่ได้
- รายการเติมน้ำแข็งเดิมยังคงตัดสต๊อก และหัวหน้า/แอดมินยกเลิกพร้อมเหตุผลได้
- POS ไม่สามารถทำให้ยอดรวมติดลบ
- คิวเก็บเงินแสดงเฉพาะร้านที่ซื้อในวันนั้นและยังมียอดต้องเก็บ
- หัวหน้าปิดวันด้วยยอดนับจริงรวมต่อชนิดได้
- ส่วนต่างไม่ถูกกล่าวโทษว่าเกิดจากโรงงานโดยอัตโนมัติ
- หลังปิดวันยอดเป็นศูนย์และวันถัดไปเริ่มจากยอดสั่งใหม่
