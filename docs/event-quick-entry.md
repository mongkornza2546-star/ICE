# เพิ่มงานและร้านอีเวนต์อย่างรวดเร็ว

ฟอร์มสร้างงานบังคับเฉพาะวันเริ่มและวันสิ้นสุด หากไม่ใส่ชื่อจะใช้ “อีเวนต์ YYYY-MM-DD” ข้อมูลผู้จัด สถานที่ และผู้ติดต่อเว้นว่างได้ การตั้งค่ารับเงินพับไว้และมีค่าเริ่มต้น แอดมินปรับได้ตามเดิม ส่วนหัวหน้ารอบสร้างข้อมูลได้โดยยังคงขอบเขตสิทธิ์การตั้งค่าการเงินเดิม

ใน “เพิ่มร้าน” พิมพ์ชื่อเพื่อสร้างร้านใหม่ หรือเปิด dropdown เพื่อเลือกร้านประจำ หากเว้นชื่อไว้ ระบบใช้เลขบูธหรือชื่ออัตโนมัติ วันที่ขายเริ่มต้นตามช่วงวันที่ของงาน

เลือก “เพิ่มหลายร้าน” ใส่ตึก/โซน เช่น `ตึก B` แล้วกรอกช่วงรหัส:

```text
A1-250
F1-40
T1-10
```

ระบบแสดง 300 ร้านก่อนบันทึก รองรับ `A1-A250`, `A1 ถึง 250` และรหัสที่มีศูนย์นำหน้า เช่น `A01-A10` สร้างได้ไม่เกิน 1,000 ร้านต่อครั้ง โดยไม่มีเพดานเดิมที่ 50 ร้านต่องาน ช่วงรหัสซ้ำในชุดเดียวจะถูกรวม และบูธที่มีอยู่ในตึก/โซนเดียวกันของงานจะถูกข้าม รวมถึงร้านที่ยกเลิกแล้ว บูธรหัสเดียวกันในงานอื่นไม่ถือว่าซ้ำ

การสร้างทั้งชุดเป็น transaction เดียวและมี request ID ป้องกันการสร้างซ้ำเมื่อส่งคำขอเดิมอีกครั้ง ร้านที่สร้างใหม่ผูกกับงานนั้นและไม่เข้าเส้นทางส่งประจำ ส่วนร้านประจำที่เลือกมาใช้ยังมีพฤติกรรมเดิม ข้อมูลติดต่อไม่เป็นเงื่อนไขบังคับในการเผยแพร่ แต่ยังตรวจวันที่ สถานะร้าน นโยบายการรับเงิน และราคากลางตามเดิม

ร้านที่สร้างเฉพาะอีเวนต์สามารถแก้ชื่อจริงจากปุ่มแก้ไขร้านในงานได้ ทั้งก่อนและหลังเผยแพร่ ชื่อและรายละเอียดบันทึกพร้อมกันผ่าน `save_event_participation_with_shop_name` โดยแอดมินหรือหัวหน้ารอบ ระบบตรวจว่าร้านนั้นเป็นของงานนี้และไม่ใช่ร้านประจำ ชื่อเว้นว่างไม่ได้เมื่อแก้ไข ประวัติรอบส่งที่สร้างแล้วคงชื่อ snapshot เดิม

รายงานความพร้อม POS ของร้านประจำกรองเฉพาะ `shops.event_job_id IS NULL` เพื่อไม่แจ้งร้านอีเวนต์ว่าขาด Payment Profile ของร้านประจำ ร้านอีเวนต์ใช้การตรวจความพร้อมและนโยบายชำระเงินของงานตามเดิม

## การนำขึ้นใช้งาน

Apply `supabase/migrations/0176_event_quick_entry_and_bulk_booths.sql` หลัง migration 0175 ก่อน deploy frontend รุ่นนี้ เนื่องจาก frontend ใช้คอลัมน์ `shops.event_job_id` และ RPC `create_event_shops` / `save_event_participation_with_shop_name` ใหม่

## ตรวจสอบ

- `npm run build`
- `npx vitest run tests/event-management-page.test.tsx tests/event-management-gateway.test.tsx tests/event-booth-ranges.test.tsx tests/pos-readiness-event-scope.test.tsx tests/shop-settings-status.test.tsx`
- `node --test tests/event-*.test.mjs`

Integration test ใช้ PGlite พร้อม trigger ตำแหน่งร้าน/คลังและ audit จริง ตรวจการสร้าง 300 บูธ การ retry การข้ามบูธซ้ำ rollback ทั้งชุดเมื่อวันที่ผิด สิทธิ์ผู้ใช้ การเผยแพร่โดยไม่มีผู้ติดต่อ การแยกร้านอีเวนต์ออกจากการสร้างรอบส่งและ sync ร้านประจำ และการแก้ชื่อร้านทั้งก่อน/หลังเผยแพร่ พร้อมตรวจสิทธิ์ ขอบเขตงาน audit และ rollback เมื่อบันทึกชื่อไม่สำเร็จ ทดสอบหน้าจอพรีวิวบน viewport มือถือ 440×956 ด้วยข้อมูลจำลอง ไม่ได้ apply migration หรือสร้างข้อมูลในระบบจริง
