# ตรวจนับเงินสดครบทุกบทบาทก่อนปิดยอด

ใช้ migration `0242_daily_close_all_cash_receivers.sql` หลัง migrations ถึง `0241`
แล้วเผยแพร่ frontend ที่มีข้อความ “เงินสดรายบุคคล”

วันที่ยังไม่ปิดยอดจะแสดงเฉพาะพนักงานส่งของ (`courier`), แอดมิน (`admin`)
และหัวหน้า (`round_lead`) ที่มีรายการเงินสดของวันนั้น รวมบัญชีที่ปิดใช้งานแล้ว
คนที่มีรายการรับ/คืนเงินสดยังต้องระบุยอดนับจริง แม้ยอดสุทธิเป็นศูนย์
และยังแสดงคนที่มียอดตามระบบหรือยอดนับเดิมไม่เป็นศูนย์เพื่อไม่ให้ตกหล่น
บัญชีที่ไม่มีรายการและไม่มียอดเงินสดจะไม่แสดงการ์ด หน้าเว็บส่งยอดศูนย์ให้อัตโนมัติ
เพื่อให้ตรงกับ RPC เดิมที่ยังต้องรับบัญชีที่เข้าเกณฑ์ครบทุกคน ไม่ต้องเพิ่ม migration
หากยอดนับต่างจากยอดตามระบบ ต้องกรอกเหตุผลของคนนั้นก่อนปิดยอด
เงื่อนไขนี้ตรวจทั้งหน้าเว็บและ RPC จึงไม่สามารถใช้หน้าเว็บเก่าส่งเฉพาะยอดพนักงานเพื่อปิดยอดได้

ยอดเงินสดร้านประจำใช้ยอดที่จัดสรรชำระจริง (`allocated_amount`)
และบทบาทผู้บันทึก ณ ตอนรับเงิน (`recorded_role`) จึงไม่รวมเงินทอน
เงินสดลูกค้าขาจรรวมตามผู้บันทึกรับ และหักเงินคืนตามผู้ยืนยันคืนเงินจริง
เงินคืนร้านประจำ/อีเวนต์จาก `refund_settlements` ที่คืนเป็นเงินสด
หักจากผู้ยืนยันคืน (`settled_by`) ตามวันที่คืนจริงในเวลาไทย
แม้ใบขายต้นทางเป็นของวันก่อนหน้า และเก็บสำเนารายการคืนในยอดปิดวันนั้น
ไม่รวมโอน/QR และรายการรับเงินร้านประจำที่ยกเลิกแล้ว
รายการลูกค้าขาจรยังใช้บทบาทปัจจุบันของผู้บันทึกตามกลไกเดิม
เนื่องจากไม่มีบทบาทย้อนหลังเก็บในรายการ

รายการรับเงินย้อนหลังใช้วันที่รับเงินจริง (`received_date_override`)
ก่อนวันที่รอบเก็บเงิน ไม่ย้ายเงินเก่ามารวมกับวันที่บันทึกข้อมูล
รายการปกติยังใช้วันที่รอบเก็บเงิน และใช้วันที่รับเงินในเวลาไทยเมื่อไม่มีรอบ
ใช้เกณฑ์เดียวกันในการคำนวณยอด เก็บรายการต้นทาง และตรวจสิทธิ์แก้ไขหลังปิดยอด

หากวันรับเงินปิดตรวจนับเงินสดแล้ว ระบบปฏิเสธการเพิ่ม ยกเลิก ลบ
หรือเปลี่ยนยอด/เจ้าของ/วันที่ของรายการเงินสดที่กระทบวันนั้น พร้อมข้อความระบุวันที่
เงินคืนสดใหม่หลังปิดตรวจนับของวันคืนเงินถูกปฏิเสธเช่นกัน
การกดซ้ำของรายการเดิมยังคืนผลเดิม และรายการโอน/QR ย้อนหลังยังใช้เงื่อนไขเดิม
วันที่เคยปิดเฉพาะสต๊อกโดยไม่มีการตรวจนับเงินสดไม่ถูกบล็อกเพิ่มด้วยกฎนี้
การตรวจใช้ lock เดียวกับปิดยอด เพื่อให้รายการเงินสดกับการปิดยอดไม่แทรกกัน

การส่งมอบเงินระหว่างพนักงานกับหัวหน้าไม่ใช่รายรับใหม่:
ยอดที่กรอกแต่ละคนต้องเทียบกับรายการที่บันทึกในชื่อคนนั้น
อย่านำเงินที่พนักงานส่งมอบไปบวกซ้ำในช่องหัวหน้า
หากแอดมินกดรับเงินแทนคนอื่น รายการนั้นจะอยู่ในช่องแอดมิน

เมื่อปิดยอด ระบบเก็บยอดตามระบบ ยอดนับจริง ส่วนต่าง เหตุผล และรายการต้นทาง
ของทั้งสามบทบาทพร้อมการปิดสต๊อกและรอบเก็บเงินในธุรกรรมเดียว
หน้าบัญชีใช้ข้อมูลเดียวกัน โดยแสดงเป็นยอดเงินสดรวมตามยอดนับจริง
และแยกส่วนต่างรายบุคคล

วันที่ปิดไปแล้วจะคงรายชื่อและยอดเดิม ไม่เพิ่มแอดมินหรือหัวหน้าย้อนหลัง
คำขอปิดยอดเดิมที่ส่งซ้ำด้วย idempotency key เดิมยังคืนผลเดิมได้
การเปลี่ยนแปลงนี้ไม่เปิดยอดเก่าหรือแก้ไขประวัติการรับเงิน
